# Spanish i18n — v4-S4 #16

A lightweight English/Español toggle for the rep-facing UI. Pure, **$0, zero
dependencies** — a flat key→string map per locale and a `t(key, locale)` lookup.

## Architecture

- **`lib/product-finder-i18n.ts`**: `LOCALES` (`en`, `es`), `DEFAULT_LOCALE = en`,
  `t(key, locale)` (falls back to English, then the key), and the `EN`/`ES`
  message maps. Every `en` value matches the existing UI text **verbatim**.
- **Store**: `locale` + `setLocale`, persisted to `localStorage["pf_locale"]`,
  hydrated on load — mirroring the `brandId` pattern.
- **`LanguageSwitcher`** in the header (mirrors `BrandSwitcher`).

## Why this is safe to ship incrementally
English is the default, and `t(key, "en")` returns the identical existing string,
so **nothing changes until a user picks Español** — the component test net (which
queries English text) stays green. Coverage is a curated, high-value set: the
header, primary actions/nav verbs, and the full v4-S4 surfaces (will-call queue,
customer portal). Widen coverage by adding keys + wrapping more strings in `t()`;
a later pass can move to a React context + pluralization.

## Usage
```tsx
const locale = useProductFinder((s) => s.locale);
// …
<button>{t("action.addToBasket", locale)}</button>
```

No 3rd-party account or env var required.
